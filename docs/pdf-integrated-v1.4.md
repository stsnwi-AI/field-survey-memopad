## ユーザー承認方針
- PDFを開くだけで図面・調査番号・写真・コメント・施工指示を復元する方式（A方式）を採用。
- 現場IDの手入力を通常操作からなくす。
- PDF編集、従来の写真・メモJSON、v1.3一括JSONを削除しない。
- 古いデータ、旧版、公開範囲を承諾なく破棄・変更しない。

## 実装済み（コード確認済み）
- app.js: makeProject() に surveyData を含め、既存PDF埋め込み添付 kantan-edit-data.json に保存。
- app.js: buildEditedPDF()→saveDocument() のPDF作成後、添付を抽出して調査データの整合性を照合。
- app.js: load() で埋め込み編集プロジェクトを復元後、surveyPDFLoaded()を呼ぶ。通常PDFは旧記録読み込み。
- survey.js: surveyPDFExport()/surveyPreparePDFSave()/surveyPDFLoaded()の連携。PDFの写真・メモを優先し、旧IndexedDBは後方互換に利用。
- survey.js: 埋め込み写真を data:image/...;base64 に限定して外部画像URLを拒否、異なる旧端末記録は保存領域へ退避。
- index.html: 「編集済みPDFを保存」を主操作とし、旧現場ID・一括JSON機能を折りたたみで残す。
- sw.js: v1.4のキャッシュ版へ変更。
- PDF編集機能、手書き、採番、通常のPDF保存、従来JSON、一括JSONは削除していない。

## 確認結果
- app.js / survey.js / sw.js の構文検査に合格。
- makeProject() の surveyData 埋め込み構造テスト合格。
- 写真埋め込みデータ形式検証の6試験合格（正常、外部URL、JavaScript URL、スキーマ違い、メモ不正、空記録）。
- GitHub開発ブランチに保存済み。main・公開サイトは変更なし。

## 未検証 / 既知のリスク
- 実PDFへの写真・コメント添付→実ファイル保存→ブラウザー再起動→別PCで再読込のエンドツーエンド試験は未実施。
- 大きい写真、多数の番号、スマホメモリ、PDF内添付の対応アプリ差、旧JSON復元の回帰試験は未実施。
- PDF内に写真・コメントが埋め込まれるので、PDFを共有した相手は調査写真・指示も閲覧・抽出できる可能性がある。現場の機密資料の配布時に注意。
- GitHub全履歴の機密情報監査は未完了。
- PDFを別アプリで加工・最適化するとPDFの再編集添付が失われる場合がある。
- 現場ごとに異なる元PDFを使う場合はPDF自体が管理単位となる。PDFが未保存の入力内容の復元は保証されない。

## 次の試験（テスト用PDFで）
1. 新開発ブランチZIPでアプリを開き、旧現場IDは未指定のままサンプルPDFを開く。
2. 番号001を付け、メモ、施工指示、写真を加える。
3. 「編集済みPDFを保存」でPDF保存後、保存PDFを別タブで開く。
4. 同じ番号001で写真・メモ・指示が戻るか確認。
5. 別のサンプルPDFで別記録を作り、ファイルを交互に開いて混線しないか確認。
6. 既存のPDF編集・JSONバックアップが維持されているか回帰確認。
7. 機密情報・外部通信を検査した後、ユーザー承認を受けて公開判断。
