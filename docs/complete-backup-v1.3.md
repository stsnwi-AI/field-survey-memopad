# Ver.1.3 開発試験：現場データの一括保存・復元
更新日：2026-11-11

## 実装対象
- PDF編集エンジンの `makeProject()` / `restoreProject()` を再利用。
- 現場ID、元PDF、ページ構成、番号・手書きなどの編集オブジェクト、写真、調査メモ、施工指示を1個の `現場調査一括_...json` にまとめる。
- PDF編集保存と従来の写真・メモ単体JSONは残す。
- 旧端末内の `latest`、`document:<fingerprint>`、`site:<id>:document:<fingerprint>` キーは削除しない。
- 復元前に置換確認を表示。現場IDとPDFを復元し、端末内の現場別保存領域へ記録する。
- 一括JSONは暗号化しない。現場写真などの機密情報に注意。

## 重要な制約
- Ver.1.3は開発試験版。実ブラウザーでのPDFと写真の一括保存・復元は未試験。
- 自動保存だけではPDFそのものは再起動時に表示しない。一括バックアップを読み込むと元PDFと編集状態を復元する方式。
- Chrome等での端末内IndexedDB容量、250MBを超えるJSON、スマホでの写真、異なる現場、旧バックアップ移行などは未検証。
- ダウンロード開始後に実際に端末へ保存されたことはユーザー自身の確認が必要。
- GitHub Pagesの公開とリポジトリのPublic変更は行っていない。

## 検証
- JS構文：合格。
- 一括JSONバリデーションの独立した簡易試験8例：合格（正しい形式、誤形式、未設定ID、PDF欠損、ページ欠損、メモ不正、画像データ不正、孤立記録保持）。
- 一括復元の統合・ブラウザー動作試験：未実施。

## 次の確認手順（テストデータのみ）
1. 開発ブランチのZIPを取得し、ローカルHTTPサーバーまたは安全な開発プレビューで開く。
2. TEST-A、サンプルPDF、番号001、メモ、画像を設定。
3. 「現場データを一括保存」を押してJSONのダウンロードを確認。
4. 別タブで初期画面を開き「一括ファイルを復元」でJSONを選択。
5. PDF・番号・メモ・画像の再現を確認。現場Bを設定して混在しないか確認。
6. 旧PDF保存・単体JSON保存が継続動作するか回帰確認。
