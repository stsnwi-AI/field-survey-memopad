## 2. ユーザー報告・確定要求
1. 調査番号をタッチ・ペンで2回続けて押したとき、連射されて隣接する番号が2個自動配置されるのを防ぐ。
2. 1枚目のPDFを既に開いて書き込み途中で2枚目を開くことを前提に、1枚目の書き込み・調査番号・写真コメント等を保持して切り替える。
3. 作業途中でPDFタブを閉じられるボタンを追加する。未保存内容を無警告で破棄しない。
4. Ver.1.4.46の縦連続スクロール表示、右側・手動開閉の色パレット、既存ペン操作と保存機能を可能な限り維持する。

## 3. 修正点
### 3-1. 調査番号の重複防止
- `survey.js`：調査番号配置を「指」「ペン」「右クリック（contextmenu）」共通の`placeFromEvent`内でガード。
- 最後の配置から850ms以内の再配置を無効化。タッチ／ペンの短い二度押し、同じ操作から派生する2回目のイベントを吸収する。
- 既存の調査番号上への新規配置を禁止。番号と写真・コメントの紐付けが上書きされないようにする。
- 正常配置後のみタイムスタンプを更新。連続採番ON時でも850ms経過後に別位置へ意図的に配置可能。
- 既存ピンを選択・長押しで写真コメント編集する処理、採番方式、PDF保存構造は維持。
- 長押しや連続採番が850ms以内で必要になる現場操作は今後実機確認が必要。

### 3-2. 既に編集中の1枚目を複数PDF画面へ移す
- `index.html`：既存の「複数PDF・縦スクロール」リンクを維持。クリック時のみ、専用の一時転送チャンネルを用意。
- 新規`workspace-handoff.js`：`BroadcastChannel`を使って同一ブラウザ／同一オリジン内で、**元の編集画面を閉じずに**現在の編集状態を新しいワークスペースへ送る。ランダムな一時トークンによる応答先照合を行い、サーバーへPDFを送信しない。
- `app.js`：`window.exportWorkspaceProject()`で元PDFバイト列、全編集オブジェクト、写真・施工指示・コメントを含む`makeProject()`、undo/redo、dirty状態をコピー。送信前に調査記録の読込完了を確認。
- `app.js`：`window.restoreWorkspaceProject()`で別のiframe内に`restoreProject()`、`surveyPDFLoaded()`を適用後、undo/redo/dirtyを戻す。元の編集画面やファイルは消さない。
- `workspace.html`：?transfer=のランダムトークンを認識し、元画面から受け取った編集途中のPDFを**最初のタブに**開く。以降「＋ PDFを追加」で2枚目以降を新規の独立したiframeへ開く。
- 既存の`workspace.html`独立iframe方式を保持。タブ切替は非アクティブiframeを非表示にするだけで、毎回loadしたり初期化しない。
- 受け渡し失敗時は元画面のPDFを維持し、エラーを表示。PDFファイルの上書きや自動ダウンロードはしない。
- **注意**：引継ぎは「コピー」なので、元の編集画面とワークスペース側のPDFはその後は別セッション。後の編集は自動同期しない。ユーザーがワークスペース側を正として使い、各PDFを明示的に保存する。
- 保持はページを開いている間のメモリ上のみ。再起動／リロード後の自動復元は未実装。

### 3-3. PDFを閉じるボタン
- `workspace.html`：PDFごとのタブ名右横に「×」ボタンを追加。
- タブを閉じる前に必ず確認ダイアログを表示。写真・コメントのみ変更された場合は`dirty`が必ずしもtrueにならないため、dirty=falseでも保存確認を省略しない。
- ユーザーが承諾した場合だけ対象のiframe・タブを閉じる。**他のPDFタブは一切変更しない。** 末尾／中間／最後のタブを閉じたときは残っているタブを表示、0件なら空の案内画面に戻す。
- 元のPDFファイル自体は削除・上書きしない。閉じたタブの未保存編集は失われる可能性あり。
